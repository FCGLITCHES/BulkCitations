# Public Launch Quality System

This is the simplified output-quality system for getting BulkReferences public quickly without a heavyweight promotion pipeline.

> Verified against code 2026-06-25: scoring/health live in `server/src/engine/phases/phase10Health.ts`
> (Phase 10 — `phase10Score.ts` is a re-export alias), weights/style sets in
> `server/src/engine/scoreConfig.ts`, and warning severities in `server/src/engine/healthWarnings.ts`.

## Goal

Keep deterministic citation output reliable while minimizing manual release steps for a solo operator.

## Pipeline

The launch pipeline, conceptually, is:

1. `ingest`
2. `normalize`
3. `parse`
4. `repair`
5. `score`
6. `review if needed`
7. `render`
8. `publish`

These map onto the live engine phases (see [phase-index.md](phase-index.md)): ingest = P1/P2, parse =
P3–P6, repair = P6.8/P6.5, normalize = P7, **score + review-status = P10 (`phase10Health`)**, render = P12,
and `publish` is the operator-side gate below (not a per-citation phase).

ML may suggest fixes or review priority, but deterministic validation owns public output.

## Engine Modes

- `stable`: public user path.
- `review`: admin path with extra warnings and review signals.
- `lab`: experimental ML or rule changes.

Experimental behavior must not silently affect `stable`.

## Autogenerated Identity

Canonical identity is generated during ingestion or normalization. The shared helper is `generateCanonicalIdentity` in `server/src/engine/ingestion/canonical.ts`.

It emits:

- `canonicalWorkKey`
- `normalizedDoi`
- `normalizedUrl`
- `normalizedTitleHash`
- `normalizedHash`
- `sourceProvenance`
- `duplicateHints`

Admins should only resolve identity conflicts when the generated identity is ambiguous.

## Style Profiles

Use simple style profiles instead of large rule-pack contracts. The shared profiles live in `server/src/engine/styleProfiles.ts`.

Each profile contains:

- required fields by reference type
- common repair rules
- abstain rules
- high-value regression examples

Git history is the rollback mechanism for style-profile changes until the product needs a heavier release system.

## Output Status

Use one shared quality status model from `server/src/engine/quality/outputQualityStatus.ts`:

- `ready`
- `repaired`
- `needs_review`
- `abstained`
- `failed`

Reason codes explain why a citation or publish gate needs attention.

## Scoring (Phase 10)

Every reference gets a `rawScore` / `displayScore` from three components — field evidence, format
correctness, structural integrity — combined with style-specific weights in `scoreConfig.ts`.

- `GUARANTEED_SCORING_STYLES` (the styles that score on the high-trust `guaranteed` path with
  `field 0.4 / format 0.35 / structural 0.25` weights) now contains **all 9 live styles**:
  `apa7`, `mla9`, `chicago-author-date`, `vancouver`, `ieee`, `harvard-ctr`, `chicago-notes-bib`,
  `ama`, `acs`. `FALLBACK_SCORING_STYLES` is **empty** — there is no silent APA fallback for scoring
  anymore (it tracks the 9 first-class CSL renderers in Phase 12).
- The format-correctness component is computed during render (`resolveFormatScoringPath`,
  `finalizeRawScore`/`finalizeDisplayScore` in `scoringHelpers.ts`).

## Health & the confident-wrong guard

Phase 10 sets the public status (`ready` / `needs_review` / `needs_action`) and attaches
`HealthWarning`s. Beyond the usual missing/invalid-mandatory-field checks, it closes the engine's
**"confident-but-wrong" blind spot** — fields that are *present* (so they would otherwise read as
`ready`) but structurally implausible (`detectImplausiblePresentFields`). These only inspect untrusted
heuristic values and only fire on clear-cut errors, so they add review signal without false-positiving:

| Warning code | Severity | Fires when |
| --- | --- | --- |
| `suspect_author_value` | `review` | an author entry carries a year / page-locator / DOI / URL / volume, or is implausibly long (a mis-segmented span swallowed an adjacent field) |
| `suspect_locator_value` | `review` | a page range's start exceeds its end |
| `author_list_incomplete` | `info` | the author span was truncated with "et al." — intentional, citation-correct truncation, surfaced without demoting status |

Severities are defined in `healthWarnings.ts` (`WARNING_SEVERITY_MAP`); BIO sequence diagnostics
(`overlapping_spans`, `unclosed_bio_sequence`, `missing_required_ml_span`) and authority/render warnings
live in the same map.

## Publish Gate

Publishing replaces promotion for the launch workflow.

The lightweight gate is `evaluatePublishGate` in `server/src/engine/publishing/publishGate.ts`.

A publish is allowed when:

- golden examples pass
- no critical failures exist
- output diffs for changed styles were reviewed
- a previous stable version exists when rollback is expected

User-facing admin actions should be:

- `Import`
- `Review`
- `Fix`
- `Validate`
- `Publish`
- `Rollback`

Avoid exposing dataset, bundle, or promotion internals in the public-launch admin workflow unless they are required for diagnosis.
