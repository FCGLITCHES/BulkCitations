BIO Tagging — Self-Improving Label Loop

The bottleneck is label quality, not model size. Build a consensus-gated loop where the LLM, the live model, and the engine projection vote — the admin touches only the disagreements — and rebuild gold on real, stratified data with reliability gates that beat a frozen baseline.

Objective: reliability on messy input Constraint: minimal admin intervention Gate: beat baseline-v1 on real eval

Two foundational decisions

Restart gold — don't delete

Quarantine the 1,200 synthetic refs & rebuild on real data

Synthetic templated rows teach the model template shapes, not real-world variety — exactly why book_title (F1 0.03), publisher (0.26) and conference_title (0.28) collapsed.

  • Flip synthetic rows to row_status: quarantined — the loader already excludes them. Nothing is lost.
  • Freeze the current ONNX model as baseline-v1 — it's the consensus "model leg" and the bar to beat.
  • Rebuild gold smaller but stratified: quality > volume for sequence labeling — with per-field minimums so rare classes don't vanish.
Minimal-admin loop

Three-way consensus, human only on conflict

Your instinct is right — LLM labels, engine fixes, you verify. The upgrade: make it a vote between three independent signals so most rows never need you.

  • LLM (GPT-5.4 nano) proposes field spans.
  • Engine projection aligns them to tokens (hardened — no silent drops).
  • Live model predicts independently.
  • Agree → auto-gold (0 admin). Disagree / ambiguous → admin. That's the only human touch.

Benchmarks — measure the product, not just the model

Users don't care whether the engine labels something APA7 vs Harvard. They care whether the final citation is usable without fixing it. Internal F1 is a health signal; the product metric is acceptance.

Crosscutting principles

1

Benchmark the output, not the internals

Style/type F1 is internal. The roadmap's north-star metric is "accept without fixing," plus export fidelity and edit distance. Internal labels never become the goal.

2

Stratify the real data

Coverage beats count. A stratified set with per-class minimums (PDF paste, Scholar, DOI-heavy, books, webpages, reports, theses, conference, broken punctuation, multilingual, malformed) — not 1,000 generic refs.

3

Reliability is the objective; throughput is a guardrail

350 refs/sec must not collapse, but it does not drive the roadmap. Users forgive a few extra seconds; they never forgive confident-wrong citations. Quality gates promotion — speed only monitors for regression.

4

Loud internally, calm externally

Two channels. Internal: structured health logs, per-phase degradation, confidence telemetry. External: clean states only — "Needs review", "Low confidence author", "Could not verify source". Never scary internals to end users.

5

The extraction-file split is move-only or it doesn't happen

A 25K-line file is fragile, but splitting before benchmarks are locked invites months of churn. Rules: do it after P0's eval harness exists; one parser group at a time; golden-output snapshot before & after each move; assert byte-identical output; zero behaviour changes, zero opportunistic fixes. If you can't prove parity, you don't move.

Sequencing

P0 Lock truth→ P1 Rebuild gold→ P2 Flywheel→ P3 Model & P4 Volume + refactor

P0→P1→P2 is the critical path — it builds the self-improving loop that gives you the fast rate. P3 (model) and P4 (volume + the careful refactor) run after, gated on the same real eval set. The single highest-leverage first action: harden the projection + stand up the real eval set — together they improve every retrain immediately and finally tell you the truth.
